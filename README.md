# Ремонтология — Laravel-версия

Полноценный сайт на Laravel 10 (PHP 8.1) с базой данных, собственной админ-панелью
и SEO-обвязкой. Вырос из статической версии в `../site/` — та осталась
рабочей как самостоятельный автономный вариант (см. её README), эта же
папка — «боевой» вариант с редактируемым через админку контентом.

## Быстрый старт

```bash
composer install
cp .env.example .env      # уже настроен на SQLite, менять не обязательно
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

Откроется на `http://localhost:8000`.

**Вход в админку:** `http://localhost:8000/admin`
— `admin@remontologiya.ru` / `remont2026` (сидируется `AdminUserSeeder`,
смените пароль после первого входа — форма пока не сделана, быстрее всего
через `php artisan tinker`: `\App\Models\User::first()->update(['password' => \Hash::make('новый-пароль')]);`).

## Что редактируется через админку

Практически весь контент сайта — без единой правки кода:

- **Настройки** — телефон, соцсети, подвал, SEO-суффикс, счётчики аналитики.
- **Калькулятор** — цены за м² по трём типам ремонта, коэффициенты сроков,
  шесть опций с ценами и признаком «включена по умолчанию».
- **Страницы (9 шт.)** — заголовок и лид шапки, две кнопки-CTA, SEO-мета,
  плюс заголовки всех тематических блоков страницы (например на главной —
  11 блоков от «Обещаний» до «Контактов»).
- **Пример сметы** — карточка на странице «Цены».
- 18 списочных справочников: услуги, тарифы, прайс (разделы + позиции),
  этапы ремонта, портфолио, отзывы, кейсы в цифрах, пункты и документы
  гарантии, команда, принципы, хронология, FAQ, статьи блога, вакансии.
  У каждого — создание/редактирование/удаление, порядок (стрелки вверх/вниз),
  и где уместно — публикация вкл/выкл.
- **Заявки** — все обращения с калькулятора и формы контактов, с пометкой
  прочитано/не прочитано.

Устройство админки — `app/Admin/ResourceRegistry.php` описывает поля
каждого из 18 справочников (тип, подписи, правила валидации), а
`app/Http/Controllers/Admin/ResourceController.php` — один общий CRUD-движок
поверх этого описания. Добавить новый справочник — значит дописать в реестр
десяток строк, а не контроллер и три вьюхи.

## SEO

- `meta title/description`, canonical, Open Graph — на каждой странице,
  берутся из `pages.meta_title/meta_description` или из самой статьи блога.
- JSON-LD: `HomeAndConstructionBusiness` на каждой странице,
  `BreadcrumbList` на внутренних страницах, `FAQPage` на главной,
  `Article` на статьях блога.
- `/sitemap.xml` — генерируется на лету, включает все статичные разделы
  и все опубликованные статьи блога.
- `/robots.txt` — закрывает `/admin` и `/storage/uploads`, указывает
  на sitemap.

## Структура

```
app/
├─ Admin/ResourceRegistry.php   ← описание 18 CRUD-справочников
├─ Models/                      ← 24 модели (1 на таблицу)
└─ Http/Controllers/
   ├─ PageController.php        ← 8 публичных страниц (кроме блога)
   ├─ BlogController.php        ← список + страница статьи
   ├─ LeadController.php        ← приём заявок (AJAX с сайта)
   ├─ SitemapController.php
   └─ Admin/                    ← вся админка

resources/views/
├─ layouts/app.blade.php        ← публичный каркас: head, шапка, подвал, SEO
├─ partials/crumbs.blade.php    ← хлебные крошки + их JSON-LD
├─ pages/                       ← 9 публичных страниц + карточка статьи
├─ sitemap.blade.php
└─ admin/
   ├─ layout.blade.php          ← каркас админки: сайдбар с разделами
   ├─ resources/{index,form,field}.blade.php  ← общие список/форма
   ├─ pages/edit.blade.php      ← форма шапки+блоков страницы
   ├─ settings/, calculator/, estimate/, leads/, auth/

database/
├─ migrations/                  ← 26 миграций
└─ seeders/                     ← весь контент исходного сайта

public/
├─ assets/css/style.css         ← дизайн-система (общая со статикой)
├─ assets/css/admin.css         ← админка на тех же токенах
├─ assets/js/app.js             ← вся интерактивность + змейка
├─ assets/js/admin.js           ← повторители полей, превью картинок
└─ img/                         ← фото из исходного комплекта
```

## Как это работает технически

- **Без сборки фронтенда.** Ни Vite, ни npm-зависимостей для стилей/скриптов
  не требуется — `public/assets/*` статические файлы, как и в `../site/`.
- **Калькулятор.** Настройки (`CalculatorSetting::current()->toJsSettings()`)
  сериализуются в `window.CALC_SETTINGS` прямо в layout; `app.js` их читает,
  с фолбэком на исходные значения демо-сайта, если переменной нет
  (так и на автономной статике, и если что-то пошло не так).
- **Секции страниц.** У каждой страницы — фиксированный набор именованных
  блоков (`pages.sections`, JSON), например у главной их 11: `promises`,
  `services`, `calc`, `pricing`, `works`, `process`, `guarantees`, `team`,
  `reviews`, `faq`, `contacts`, `footer_cta`. Список ключей на каждую
  страницу — в `PageContentController::sectionMap()`.
- **Картинки.** Свои (сид-комплект) лежат в `public/img/*.webp` и в БД
  хранятся как `/img/...`. Загруженные через админку — через `Storage`
  (`storage/app/public` → симлинк `public/storage`), в БД — `/storage/uploads/...`.
- **Лиды.** Формы на сайте отправляют `fetch()` на `POST /leads` с
  CSRF-токеном (оба берутся из `<meta>` в `<head>`); если JS/сеть недоступны,
  форма всё равно показывает «Заявка принята» — просто без записи в БД.
- **Заявки не отправляют e-mail** — только сохраняются в таблицу `leads`
  и видны в админке. Если нужны письма/интеграции — это следующий шаг,
  не реализовано.

## Известные ограничения (сознательно не делали)

- Одна учётная запись администратора, без ролей и прав.
- Нет WYSIWYG-редактора для текста статей блога (обычный textarea,
  абзацы — через пустую строку).
- Нет истории изменений / черновиков — сохранение сразу публикует.
- Форма смены пароля в самой админке не сделана (см. «Быстрый старт»).
- SQLite достаточно для демо/небольшого сайта; для реальной нагрузки
  стоит переключиться на MySQL/PostgreSQL — меняется только `.env`,
  код не завязан на конкретную СУБД.
